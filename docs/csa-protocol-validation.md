# CSA v1.2.1照合とローカル検証

2026-10-30 UTC。[CSA公式サーバ仕様](https://www.computer-shogi.org/protocol/tcp_ip_server_121.html)と
[公式クライアント要件](https://www.computer-shogi.org/protocol/tcp_ip_client_121.html)で照合した。
大会固有条件は[第7回電竜戦の計画](learning-three-round-plan.md)で区別する。
実大会サーバーへのログイン・応募はしていない。

## 照合で修正した点

- 文書版1.2.1でも、通知の`Protocol_Version`は1.2。
- フィッシャー加算は手番開始前。加算後の残時間を消費し尽くす境界を時間切れとする。
- 消費時間はサーバーの`T`情報を採用し、自分の処理時間や通信遅延を二重に引かない。
- 対局条件は入れ子の`Time+`/`Time-`と`Position`を解釈する。履歴・時計を復元して`To_Move`と照合する。
- 自分の手はサーバーの確認を待って一度だけ盤面へ反映する。手番外送信・不一致の確認では停止する。
- 詰ませた側は相手の投了と結果通知を待つ。詰まされた側は投了を送り、結果確認前に切断しない。
- 512手境界でも反則となる連続王手の千日手を単なる手数引分へ変換しない。

先のv3準備に用いたローカル6局は、公式照合前の試作時計で実行されていた。
全657手と記録時間を修正後の判定へ再生し、勝敗・終局理由・最終残時間が全て一致したことを確認した。
境界や加算前後の違いがその6局の勝敗へ影響しなかったという検査で、通信互換性の証明とは分ける。

## 実装と検査

`shogi_auto.csa.Session`は、渡されたsocket上で認証・対局条件・Agree・Start・手と時刻の確認・
宣言・終局・Logoutを扱う。ASCII/LFの分割・合流、行長、受信期限を制限し、LOGINの記録を伏せる。
条件の相違ではAgreeせず、切断後に勝手な再接続や対局再開をしない。
ローカル障害とサーバー確認済みの勝敗を区別し、色が未確定の障害へ引分を与えない。
相手の持ち時間内に3秒以上の思考があり得るため、実対局の待機期限は残時間を反映する。
短い受信期限は模擬試験だけで明示指定する。

13の通信テストと8つの大会ルールテストで、次を確認している。
認証失敗、途中Summary切断、先後別条件、履歴復元、Agree重複防止、開始4手、手番、確認不一致、
サーバー消費時間、宣言、投了待ち、時間切れ、打切り得点、中断、切断、Logout。
宣言・手数境界の一部は制御した局面・カウンタのfixtureで検査し、実対局や棋力の実績へ数えない。

```bash
.venv/bin/python -m unittest discover -s tests -p test_csa.py -v
.venv/bin/python scripts/csa_mock_smoke.py
```

後者は127.0.0.1の一時TCPポートで、ダミー認証の2クライアントと模擬審判を接続する。
今回105手を2.79秒で完了し、投了確認・Logoutまで到達した。
両クライアントと審判の盤面・残時間が一致し、通常勝敗と大会得点も一致した。
これは実TCPの機能試験で、学習回数にも、モデルの強さの比較にも含めない。

## v3比較の保全

GPU資材は引き渡し済みのNotebookを維持する。
CPU短時間比較は`71f8cd513399dfc00d48baff22a796affee9edbb`の独立したチェックアウトで行い、
同梱アプリ内容SHA `32bf855152e97a5a590ccab56ff5cbaba9867ac13cccd3fbbf0c8d3ac76b6610`との一致を確認済み。
こちらは0.1秒・384手・引分0.5の固定スクリーニングで、大会時計を実行しない。
v3の大会ルール対局は修正後の時計を両モデルへ適用して別集計する。
時計の改善を学習による棋力向上と混同しない。

実サーバーの認証・ネットワーク品質・独自拡張との互換性は未検証。
外部サーバーへの接続を行うCLIや自動接続は用意しておらず、次のGPU反復も開始していない。
