# 追加2回目 / v4：教師探索と価値学習の見直し

[v3の対局・監査](learning-round3-results.md)完了を受けて、この方法を確定した。v4は未学習で、追加3回のうち2回目に当たる。
[3回の事前計画](learning-three-round-plan.md)と[教師の利用条件](learning-policy-v2-plan.md)を維持する。

## 根拠と仮説

v3はvalidationのCE＋MSEが3.4061から3.2093へ下がり、価値MSEは0.2861から0.2113へ下がった。
固定短時間比較では学習前に49勝14敗1分、材料評価に38勝24敗2分、NNUE教師に0勝64敗だった。
材料評価への95%ペアbootstrap区間は0.4844〜0.7344で、優位とは断定しない。
教師との差が大きい一方、探索深さは平均4手程度あり、以前の探索停止問題と同一視しない。
少数の大会ルール対局も教師に0勝2敗で、通信・時計の異常はなかった。

訓練splitだけを調べると、v3の9,636行のうち5,643行（約58.6%）は教師価値の絶対値が0.95を超える。
これは`tanh(cp/600)`で極端な評価となった局面で、校正した勝率とは解釈しない。
互角付近の局面の学習機会と価値損失の比重を増やし、教師の探索量も増やす仮説を試す。
戦術を解けるようになる保証や最適性の主張はしない。

## 変更する点

- 新しい名前空間`denryusen-dr7-round4`・seed20261112で384軌跡、各24採取候補、最大160手。
  開始4手を含め、教師65,536ノード／軌跡4,096ノード（v3のそれぞれ2倍）。
- 各データsplitをゲーム単位で分離する。旧データと既存の開発対局の全到達局面を除外し、
  v3のvalidation/testを訓練へ混ぜない。再利用はv3のtrain 9,636行だけ。
- train内の`abs(value)<=0.95`の行の抽出重みを2、それ以外を1とする。
  epochごとにtrainの行数だけ復元抽出し、seed＋epochで再現する。
  重み1では従来の全行permutationを保ち、validation/testの抽出・指標には重みを適用しない。
- 損失は訓練時だけCE＋2×MSE。選択指標は従来どおりvalidationの非平滑CE＋MSE。
  損失重みと再抽出の効果を個別に特定できる実験とは扱わない。

モデル構造、特徴、探索アルゴリズム、合法手マスク、教師のバイナリ・NNUE・USI設定は維持する。
初期モデルはv3のvalidation選択重み
`99600837fb9af11e5e7c21921adf77eaa434e33a63be15065f261e4552c23d8e`。
学習率0.0003、weight decay0.03、合法手label smoothing0.05、batch128、seed314162、
最大40epoch・最小6epoch・validation改善なし6epochで早期終了。
新しいデータに対する初期指標と選択指標を比べ、異なるvalidation集合のv3値と直接比較しない。

## 比較・予算・受渡し

v4の開発対局はseed20261122、32開始局面・先後交換、0.1秒・384手で行う。
学習直前／固定材料評価／固定教師／学習直前対固定教師に加え、保存済み固定v2との64局を加えた320局。
同じ探索を全ニューラルモデルに使い、通常得点・ペア単位の不確かさ・異常を記録する。
大会ルールの少数対局は修正後時計を使い、短時間比較から分ける。
testは計算せず、3回のモデルを固定した後の共通最終評価まで保留する。

CPU生成は累計1800秒、短時間対局は3600秒を上限とする。
GPU学習は累計1200秒、Notebook全体1500秒＋終了猶予15秒。親側が無料残量とOFFを確認する。
CPUの少量機能確認をGPU学習・棋力改善・追加回の完了へ数えない。
入力生成とNotebook生成は、v3の実更新・対局完了・選択重み・test保留を記録した監査結果を要求する。
第三者の棋譜・バイナリや重みを非公開入力へ追加せず、自分のモデルと自己生成配列だけを渡す。
応募・実大会ログイン・課金・追加GPUの自動起動は行わない。
