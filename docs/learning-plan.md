## 実験v1の事前設定

- 生データ：seedを固定した自前の160ゲームから各4局面まで採取。軌跡生成は捕獲等を優先しつつ確率的に合法手を選び、ランダム対戦成績を棋力の証拠にはしない。
- 教師：現在の材料評価を固定し、最大2手先・4096ノード・最大2秒で探索。**2手先まで完了した局面だけ**使い、完成しなかったラベルは除外。教師の限界を隠さない。
- 学生：14駒種×81マス＋持ち駒7種の1141特徴から、材料評価への補正を学習。補正は±600cpで制限。PyTorchの線形モデルで、NNUEやdlshogi本体ではない。
- 初期モデル：seed固定の小さな乱数。比較用に保存し、学習後と同じ探索・特徴量・補正上限を使う。
- 分割：ゲームID単位でtrain/validation/test。完全一致と左右反転が同じ特徴になる局面も、分割をまたがないよう除重複。
- 学習：seed固定、AdamW、最大200epoch。validation MSEだけでモデルを選び、testや対局の成績で選び直さない。
- 対局：学習後対固定材料評価、学習後対初期モデル。それぞれ32開始局面×先後2局＝64局、合計128局。
  開始局面は学習・validation・testの入力と重ならない、材料差±200cp以内・王手なしの12手までの合法な局面。
  両者0.05秒の探索予算、同じ6000ノード上限。異常な思考時間は0.5秒（または予算の5倍）を超えたら時間負けとして記録。
  通信を含む大会公式の時計条件ではない。
- 最大256手で区切り、実験上のmove_limit引き分けとして別集計。詰み・通常千日手・連続王手も別集計。
- 不確かさ：開始局面の先後ペアを単位にbootstrap 95%区間と、保守的なHoeffding 95%境界を併記。
  同じ開始局面の2局を独立な標本2件とは扱わない。
- 成功主張：各比較30ペア以上完了、保守的下限が0.5超、異常終了ゼロ、move_limitが20%以下の場合だけ改善の証拠ありとする。
  これは事前に決めた小規模実験内の証拠であり、段級位・Elo・大会順位を保証しない。

CPU時間依存の探索なので、異なる機種では教師の到達深さや対局結果が変わりうる。
再学習の再現単位は保存済みcorpus＋SHA-256・設定・seed・コードであり、別ハードで局面を再生成してビット一致するとは約束しない。

## 実行と必要資材

通常の対局UIは追加依存なしで維持する。学習は任意のNumPy/PyTorchが必要。
Kaggleでは既存のPyTorch/CUDAをそのまま使い、インストール・更新しない。
今回cshogiも比較したが、Python 3.12向け配布版がNumPy<1.27を要求したため、Kaggle環境を変更せず既存python-shogiを利用する。

CPUでの実行例（PyTorchは[公式手順](https://pytorch.org/get-started/locally/)でCPU版を用意）：

```bash
source .venv/bin/activate
python -m pip install -e '.[learning]'
python -m shogi_auto.learning.run --run-dir runs/cpu-learning-v1 --device cpu
```

Kaggleは `notebooks/kaggle_learning_v1.ipynb` を非公開NotebookへImportする。
公開コードとpython-shogiのソース・GPL本文を内包するため、Internet OFFのまま実行できる。
外部データのアップロード、モデルのダウンロード、APIキーは不要。
Notebook作成スクリプトは `scripts/build_learning_notebook.py`。元コードと同梱元バージョン・SHAを記録する。

実行直前に親側のブラウザ担当が無料GPU残量をUIで再確認し、Notebook先頭の `REMAINING_FREE_GPU_HOURS` に入力する。
2時間未満・未確認なら起動しない。GPU選択はT4×2（既知の動作確認環境）。1GPU上で学習し、割当は見えるGPU数で保守的に計上する。
コードには外部の個人データを含まない。未承認の追加インストール・権限・課金・新APIキー要求時は停止し、相談する。

## 保存・中断・再開・停止

- 出力先：`/kaggle/working/shogi-learning-v1/`。corpus、分割、設定、元commit/source SHA、モデルJSON、optimizer入りcheckpoint、epochログ、対局棋譜、時間、結果、依存版・GPU名を保存。
- データ生成はゲームごと、学習はepochごと、対局は1局ごとに追記・保存。checkpointは `weights_only=True` で自分の保存物のみ読み込む。
- 同じコード・設定・run directoryで再開する。途中データやcheckpointの識別子が一致しなければ拒否する。累積壁時計予算はリセットしない。
- 実験プロセスは2400秒の協調予算、Notebook全体は3000秒の監視上限と終了猶予20秒。T4×2でも2 GPU時間より余裕を残す。
  終了後ただちにセッションOFF。Notebook外のアイドル時間はコードで止められないため、親側担当が管理する。
- 予算到達は `paused`、例外は `failed`。全対局が終わらない限り完了としない。残量不足なら保管して本人判断を待つ。
- 強くならない場合：教師の2手探索の質、局面数、線形表現の限界、CPU推論の探索量低下、千日手率を確認する。
  次は別seedの評価局面を使い、強い教師（利用条件を確認したもの）や小型非線形価値・方策モデルを別実験で比較する。
  固定テストで都合の良い版を選ぶ操作を繰り返さない。

モデル・自前棋譜・checkpoint等はGitに入れず、非公開Outputで保管する。
今回の目標管理に登録する正式なツールは子環境にないため、登録完了とは主張しない。
